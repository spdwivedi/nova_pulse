# `src/audio/` — Procedural WebAudio Synthesizer

The `audio` module generates all sound effects entirely in-browser using the Web Audio API. No audio files are loaded or fetched — every sound is procedurally synthesized from oscillators, noise sources, and gain envelopes. The synthesizer degrades silently in headless environments (Node.js test runner) — all methods are safe to call unconditionally.

---

## Files

### `sound_synth.js` — `SoundSynth`

#### AudioContext Initialization & Autoplay Policy

Modern browsers require a user gesture before allowing `AudioContext` to produce sound. `SoundSynth` defers `AudioContext` creation to the first call to any play method after a user interaction has occurred. If called before a gesture (e.g., during the first frame before any input), it silently no-ops.

```js
_ensureContext() {
  if (this._ctx) return true;
  try {
    this._ctx = new (window.AudioContext || window.webkitAudioContext)();
    this._masterGain = this._ctx.createGain();
    this._masterGain.connect(this._ctx.destination);
    this._masterGain.gain.value = this._isMuted ? 0 : 0.4;
    return true;
  } catch {
    return false;   // No AudioContext (Node.js) — graceful no-op
  }
}
```

The `_masterGain` node sits between all sound nodes and the audio destination. Muting simply sets `_masterGain.gain.value = 0` — all scheduled audio continues internally but produces no output, allowing instant unmute without audio discontinuities.

#### `playLaser(freq = 820, duration = 0.08)`

Synthesizes a descending sawtooth laser pulse:

```
OscillatorNode (sawtooth, freq Hz)
  → GainNode (envelope: 0 → 0.6 → 0, attack 0.003s, decay=duration)
  → BiquadFilterNode (highpass, ~500 Hz, cuts low mud)
  → _masterGain
  → destination
```

Frequency sweep: `osc.frequency.setValueAtTime(freq, t0)` → `osc.frequency.exponentialRampToValueAtTime(freq * 0.3, t0 + duration)` — creates the characteristic "pew" pitch drop.

**Used for**: Plasma cannon shots, hunter spore emission.

```js
soundSynth.playLaser(820, 0.08);    // player cannon: high-pitch short burst
soundSynth.playLaser(640, 0.05);    // crimson hunter: lower pitch, shorter
```

---

#### `playImpact(volume = 0.8)`

Synthesizes a sharp percussion hit using white noise filtered through a bandpass:

```
BufferSourceNode (white noise, 0.12s buffer)
  → BiquadFilterNode (bandpass, ~3500 Hz, Q=2.5 — percussive crack)
  → GainNode (envelope: 0 → volume → 0, attack 0.002s, release 0.05s)
  → _masterGain
  → destination
```

White noise is generated by filling a `Float32Array` with `Math.random() * 2 - 1` samples. A new buffer is created per call (short — 0.12s at 44.1 kHz = ~5,300 samples). This is the only allocation in `SoundSynth` — unavoidable for noise generation without a pre-allocated noise buffer.

**Used for**: Projectile impacts on entities, mine proximity trigger.

---

#### `playExplosion(volume = 1.0)`

Synthesizes a low-frequency explosion rumble:

```
OscillatorNode (sine, 65 Hz → 15 Hz sweep)
  → GainNode (envelope: 0 → volume → 0, attack 0.005s, release 0.6s)
  → _masterGain
  → destination

+ simultaneous:
BufferSourceNode (white noise, 0.3s)
  → BiquadFilterNode (lowpass, ~400 Hz, Q=1 — thick thud)
  → GainNode (volume × 0.4)
  → _masterGain
```

The sine frequency sweep (65 → 15 Hz) produces the sub-bass "thump", while the low-pass noise adds the "whomp" body texture.

**Used for**: Enemy/boss death explosions, Nova Bomb detonation, mine blasts.

```js
soundSynth.playExplosion(0.6);   // standard enemy death
soundSynth.playExplosion(1.0);   // boss death / Nova Bomb
```

---

#### `playThruster(isActive, intensity = 1.0)`

Synthesizes a continuous thruster drone. Unlike other methods which create one-shot sounds, `playThruster` manages a persistent `OscillatorNode`:

**On**: `isActive = true`
- If thruster node not running, creates a modulated noise drone:
  ```
  OscillatorNode (sawtooth, 180 Hz base)
    → WaveShaperNode (soft-clip distortion — adds harmonics)
    → BiquadFilterNode (bandpass, ~900 Hz + intensity × 300 Hz)
    → GainNode (volume = intensity × 0.15)
    → _masterGain
  ```
  - `_thrusterGain.gain.setValueAtTime(0)` → `linearRampToValueAtTime(target, 0.1s)` (smooth fade-in)

**Off**: `isActive = false`
- `_thrusterGain.gain.linearRampToValueAtTime(0, now + 0.08)` (smooth fade-out)
- Then `_thrusterOsc.stop(now + 0.08)` — clean disconnect

**Intensity modulation** (when already running):
- `_thrusterFilter.frequency.setTargetAtTime(900 + intensity × 300, now, 0.05s)` — adjusts pitch in real-time

**Used for**: Flagship manual thruster activity (volume and pitch scale with thrust magnitude).

---

#### `toggleMute()` → `boolean`

```js
const nowMuted = soundSynth.toggleMute();
// Returns new muted state (true = muted)
```

Toggles `_masterGain.gain.value` between `0.0` (muted) and `0.4` (nominal). All currently playing sounds continue internally — toggling unmute does not replay anything.

```js
soundSynth.isMuted;   // current mute state (read-only)
```

## Node.js Compatibility

All `SoundSynth` methods check `_ensureContext()` before doing any audio work. In Node.js, `window.AudioContext` is `undefined`, so `_ensureContext()` returns `false` immediately and all play methods return without error. This allows the test suite to import and instantiate `SoundSynth` without a DOM.

```js
// From tests/engine.test.js (Phase 4 suite)
const synth = new SoundSynth();
synth.playLaser(820, 0.08);   // no-op in Node — does not throw
synth.playExplosion(1.0);     // no-op in Node — does not throw
assert.equal(synth.isMuted, false);
synth.toggleMute();
assert.equal(synth.isMuted, true);
// ✓ All assertions pass in headless Node
```

## Audio Graph Overview

```
                    [Oscillator / Noise / BufferSource]
                              │
                         [Filter / Shaper]
                              │
                         [Envelope Gain]
                              │
                         ┌────▼─────┐
                         │  master  │  ← toggleMute() controls gain.value
                         │  Gain    │
                         └────┬─────┘
                              │
                         [AudioDestination]
                          (speakers)
```

Multiple concurrent sound sources all route through the single `_masterGain` node. The Web Audio API's underlying audio graph handles mixing automatically — up to dozens of simultaneous sources are mixed in the browser's audio worklet thread, completely off the JavaScript main thread.

---

## Performance Notes

WebAudio processing runs on a **dedicated audio worklet thread**, separate from the JavaScript simulation thread. The synthesis CPU cost therefore has **zero impact** on physics/render frame timing. Even `playExplosion`'s multi-node graph setup (which creates ~4 nodes) takes < 0.1 ms on the JS thread — the audio rendering happens asynchronously.

The only GC-relevant operation is the white noise `Float32Array` allocation in `playImpact` (~5,300 floats = 21 KB). This occurs at most a few times per second and is within the minor GC threshold for V8 — it will not cause major GC pauses.
